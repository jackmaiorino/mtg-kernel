# CI scopes (release line)

Generated by `python tools/ci/ci_scope.py markdown` from `tools/ci/ci_scope.py`; `tools/ci/tests/test_ci_scope.py` fails if this file and the table differ.

A ready pull request whose files all qualify for release-trainer runs only that scope. Any other file, any merge commit in the pull request (a merge between this line and main), or a pull request of more than 250 commits (the listing limit), runs the whole pull request set. Markdown files never decide. `ci:full` forces the whole set on the next push or ready (a label alone starts no run); labels never narrow a run. Pushes to the line run the full matrix as a monitor, coalesced as on main (one running, one waiting, a newer merge replaces the waiting one); a red monitor's report names every merge it covers, and a red shard there is fixed forward or reverted the same day.

## Scope to checks

| scope | ci.yml jobs | what runs |
|---|---|---|
| pr | the whole pull request set | every job of the pull request set |
| release-trainer | rust-quality, trainer-tests | formatting and Clippy, plus the library tests of the trainer modules and of every qualifying shared module in full (TRAINER_FILTERS), Linux |
| docs | none | nothing |

Library test filters: `expanded_deck_training_v1::`, `native_policy_train_step_v1::`, `native_expanded_training_run_v1::`, `native_policy_value_net_v1::`, `training_math_v1::`, `native_flat_tensorizer_v`, `inference_cache_v1::`, `native_train_state_payload_v1::`, `native_trainer_schedule_v`, `native_trainer_v1::`, `native_training_`, `native_checkpoint_`, `native_baseline_checkpoint_chain_v4::`, `fast_sampler::`, `unclamped_softmax_sampler_v1::`, `s_transformer_v1::`, `native_opponent_sampler_v1::`, `sideboard_play_policy_v1::`, `rl_session::`.

Rows: Linux with `default features`, `experimental-burn-net8-packed-cuda-v1,gpu-exact-v1`, `limited-fdn-fixtures`, `limited-fdn-fixtures,native-training-store-v2-production`, `standard-magezero-fixtures`, `eternal-fixtures`, `gameplay-decision-trace-v1`, `viewer-recording-v1,flat-action-diagnostic,tensorize-cost-profile-v1,s4a-profile-v1,native-training-store-v2-production,gpu-exact-fault-injection-v1`, and Windows with default features. A default row runs every library test the filters select; another row runs the selected tests its build compiles and the default build does not, plus the selected tests the full pull request set's own commands with the same feature set run, so no row is weaker than the full set (`tools/ci/rust_test_cfg.py`, checked against the compiled inventory on every run). Selected tests that compile only on Windows with other features are not run here, as in the pull request set.

release-trainer scope: CI runs formatting, Clippy and the library tests of the trainer and qualifying shared modules only. Mandatory bit-identity rows, run on a node, not in CI: the production 10-game recipe; the production 60-game recipe; the pilot recipe with mulligans; the pilot recipe with mulligans and priority windows (keep lean present), on the znver5 build and on the portable build, and on native arm64 when Mac arms use that build. A change that adds a recipe field also needs those rows with the field absent and the feature's own differential tests with it present. A trainer pull request without those rows linked is not mergeable under the merge rule, whatever CI says.

Production recipes do not exercise sideboarding or every observation path, so the bit-identity rows are blind there and these unit suites are the only gate; that is why the shared modules run in full.

Engine rules and card changes that alter play are never bit-identical by scope: outside the qualifying list they run the whole pull request set, and, if a running lineage's trainer would pick them up, need a declaration.
