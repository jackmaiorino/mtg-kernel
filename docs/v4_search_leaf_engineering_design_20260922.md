# V4 search leaf evaluator: bounded engineering design

Decision: follow the independent search-candidate review's next step, a V4 information-set search evaluator under S0 engineering. The narrow certificate controller is not the next playing candidate; its two executed proofs remain correctness fixtures. No new games, training, playing package or gated measurement. Literature remains collab/lit/20260922-search-redirect-preparation.md; additional whole-match literature/power contract is required before a gate.

Implement an additive, explicitly V4 leaf scorer over an immutable live session and validated frozen V4 policy. Use a new local FlatDecisionEncoderV4, owned scoring buffers, fresh extensions from that live decision, and NativeFlatTensorizerV4 for every call. Do not reuse the incumbent's mutable encoder, cached extensions, sampling scratch or RNG. This resolves successor-state dependence through fresh scratch plus tests of alternating leaves and call-order independence; same dimensions never justify V2/V4 interchange. Reject terminal, stale-decision, legal-count or generation mismatch.

The existing forward_search_deterministic_v1 validates the original model contract; it cannot accept V4 input by casting an identity. Add a separate V4 search-forward entry that validates feature_transfer_config_v4 and uses the existing deterministic activation mode and pinned-MXCSR check. Preserve forward_feature_transfer_v4 and all existing scoring/training/sampling paths. Input tensor bytes must match the ordinary V4 encoder; normal-vs-search output differences from the intentional activation mode must be recorded, not assumed byte-identical. Reuse the existing search prior conversion and value-domain/quantization machinery without admitting a V4 model to the old V2 authority.

Acceptance: matching V4 tensor bits against current frozen-policy scoring on fixed live fixtures; repeated/call-order-independent search outputs; unchanged original session and sampler; explicit wrong-generation/terminal/count rejection; actor-visible-equivalent hidden-state perturbations and redeterminization controls; loaded g115 exact model/feature identity checked through this scorer. Use already consumed captured inputs or fixed constructed roots, no new matches. The certificate roots remain fixtures, not development selection targets. Small owner-checked builds use four BelowNormal jobs; no GPU inference, paid compute or guard bypass. Record any unsupported g115 import/forward boundary as a failure, not implicit fallback.

Future route requires distinct search identity and separate base-sample versus executed-action recording. All three disabled-search guards (package loader, BO3 collector, learning preparation) remain unchanged; wrapped records must not silently enter training. S0 success cannot authorize S1/S2/S3 seeds or a match gate. Before any such measurement, define the actual fixed-checkpoint estimand and cluster power; training n=0 for fixed g115, with .76pp/1.39pp applying only to properly stated cross-training-run claims. Existing matched control vectors are available for design, not a guarantee of treatment variance. M1 still requires whole-match non-regression; BO3 winner-dependent chooser coupling blocks a shortcut proof.
