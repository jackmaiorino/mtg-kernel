# Live human life Ward decisions

Issue110 source design, based on 9aad32230f7178899ef298fb07ed9951af2b1610.
Read-only source review confirms the boundaries below. The explicit session
mode, life-aware installation, private input and complete binding are now
implemented in source, with three registered backend test groups unrun.
Safe human DTOs, labels, submission and retry handling, native qualification
and actual Sire gameplay remain pending. This is an in-process human adapter,
with no model, BO3 runner or evaluation claim.

The current Human V1/V4 paths request V6. Session installation also obtains
V6 extensions before candidate normalization, so replacing only the human
projector cannot admit front-face life Ward. Add an explicit HumanV8 session
mode and constructor. Preserve every predecessor constructor, cache, schema
and scorer identity. Installation uses life-aware common extension authority
to normalize the executable candidates without creating a predecessor cache.
Retain library ordering, authenticated historical trigger sources and forced
attacker filtering. A life fee must never be represented as generic mana.

Add `human_current_decision_input_v8`, returning typed V8, the exact ordered
executable menu and a distinct backend-only binding. Validate the expected
decision, environment revision, raw origin menu and normalized candidates.
Bind the ordered menu and the complete V8 visible commitment, including life
payments and traits. Before submission, rederive the binding and then apply
the privately mapped engine index through `session.step`. Prompt numbers,
complete-menu sorting and identical-retry receipts retain their existing
semantics. Stale, forged or conflicting requests leave the session unchanged.

Use a successor safe decision/state/extension DTO. Reuse typed public-card
projection and unaffected label helpers. Register current public stack
producers and authenticated V7 historical contexts before resolving relations.
Life payment rows name safe source handles, payer and the exact public targeter
ordinal. Trait rows name a safe handle, printed fee/face and effective status.
Canonical handle ordering includes these new relations, including distinct
same-name incarnations. No arena identifier, generation, private binding or
unprojected card crosses the boundary. Do not convert complete V8 into a
purported V6 observation or serialize raw observations for later sanitization.

For pending life Ward, validate the acting payer, pending source, PayCost
purpose and exact targeter ordinal before labeling each legal Boolean:
"Pay 7 life..." or "Decline to pay 7 life...", with safe source and stack
handles. Include the payer's visible life. Exact-life payment remains legal
and may end the game; insufficient life follows the engine's actual menu or
automatic resolution. Preserve complete-prompt refusal for unrelated actions
whose meaning cannot be represented. Printed fee and effective status remain
separate when an Aura suppresses the ability.

Qualification must cover both seats, pay/decline and exact-life terminal
payment, insufficient life, save/restore replay, two targeters sharing one
source, source departure/blink and suppression. Wrong seat, stale or altered
binding/menu, invalid action and conflicting retry must preserve state;
identical retry applies once. Hidden-card substitutions and nonmonotonic
arena renumbering must preserve prompt bytes and expose no private keys.
Existing ordinary/Generic Human V1/V4 fixtures retain bytes and mappings.
Search and compulsory combat fixtures test life-aware normalization. Actual
front-life session fixtures require separately registered Sire; unregistered
source and registered predecessor fixtures are not gameplay admission.
