# Teaching checkpoints need an explicit inference adapter

Read-only source audit while Kimi's control-variance qualification owns the compute window. The equal128 comparison is still unmeasured. This note prepares the conditional next step; it does not admit a candidate, change the frozen comparison, or launch matches.

The teaching checkpoint cannot be passed directly to the ordinary whole-match or human package loader. `expanded_deck_training_v1.rs::read_ordinary_checkpoint_v1` requires an ordinary checkpoint schema, and `restore_checkpoint_fields_v1` accepts only the terminal-REINFORCE/value or GAE loss identities. Our cross-entropy-plus-retention checkpoint intentionally has a different schema and loss. Rewriting its header to an RL identity would misrepresent its objective and provenance.

There is an existing compatible integration pattern: `load_expanded_inference_v1` dispatches the explicitly tagged BO3 gameplay source to `phase1_bo3_learning_v1::load_bo3_inference_v1`, while ordinary training initialization continues to reject that source. A narrow teaching source can follow the same inference-only pattern. Its descriptor should bind the original source, actual final checkpoint, design, correct-label arm and original32 predecessor. The loader should reuse the verified equal-budget restoration checks rather than invent a second permissive checkpoint decoder. It must reject the incorrect-label semantic control as a playing source, early endpoints, incompatible features and modified optimizer state.

Use `inference_identity_v1` to report the actual installed model, new checkpoint hash, full state hash and Adam age. `FrozenPlayPolicyV1::replace_training_parameters_v3` validates the model and refreshes copied sideboard embeddings; `actual_model_identity_v1` hashes the installed parameters. Keeping the original import receipt as ancestry is supported, provided the candidate checkpoint and actual weights are separately identified. This does not reset optimizer state or authorize an RL objective transition.

The existing match collector cannot simply receive the old g115 behavior package with replaced weights. `phase1_bo3_collection_v1::collect_loaded_inner` verifies both seats' actual model identities and sampler identities against their packages, in addition to full observation-generation equality. `HumanMatchServiceV2::new` also loads the complete package through the supported component loader. Reuse these paths and their checks. A learned sideboard head bound to parent embeddings must not be assumed compatible with updated embeddings; retain the same explicit sideboard/opening policies in candidate and control for an initial gameplay comparison, and report that limitation.

After the equal-budget experiment resolves, a passing candidate would need: (1) the inference-only source loader and package construction, with exact training-tensor scores/full state replay and malformed-source rejection; (2) one bounded engine match and fresh byte-identical replay through the real package path, including seat swap and recorded legal-action mapping; and (3) a separately frozen, qualified comparison against a common fixed opponent with paired environment seeds, all eight decks, both seats and terminal match outcomes. Current-engine BO3 costs, non-natural endings, opening/sideboard restrictions and matchup cells must be reported. Do not reinterpret historical policy TV or synthetic fixture accuracy as wins. Human deployment remains a separate evidence step; the existing g115 preview stays unchanged.
