## 1. Collection sampler `unclamped-softmax-f64-icdf-u53-v1`

Code: `mtg-kernel/src/unclamped_softmax_sampler_v1.rs`. Replica: `python/tools/unclamped_softmax_sampler_v1_replica.py`. `fast_sampler.rs` is unchanged: its Q8 gap quantization and 16-nat clamp (`fast_sampler.rs:29`, `:44`) remain the deployment and evaluation samplers. The law is a finite-precision approximation of the unclamped softmax, not an exact one.

Rule (canonical contract JSON in the module, SHA-256 `61e91239...2b00`), for 1 to 65,536 finite binary32 logits:

1. Gaps `d_i = f64(z_i) - f64(z_max)` from the first maximal logit. Every maximal logit gets weight exactly 1.
2. Weight `w_i = exp_v1(d_i)` for `d_i >= -708`, else `+0.0`. `exp_v1` uses no platform math library: two-part ln 2 reduction, Horner over `RN(1/j!)` for j = 13..0, exact `2^k` scaling.
3. Sequential prefix sums `C_i` in legal-action order, `S = C_(n-1)`.
4. Draw: exactly one `next_u64` of the acting seat's continuing SplitMix64 stream, never reseeded; `u = (x >> 11) * 2^-53`, `t = u*S`.
5. Select the smallest index with `C_i > t`. `t < S` for every draw, so a selection always exists; the check fails closed. Zero-weight actions are never selected.
6. Every call verifies the pinned MXCSR (round-to-nearest-even, FTZ and DAZ off) and fails closed otherwise.

### Envelope and its derivation

Claim: `|P(i) - p_i| <= (4n + 16) u` for every action, with `u = 2^-53`, `n` the menu width, `P(i)` the selection probability over the `2^53` draw grid and `p_i` the real-valued softmax of the same binary32 logits.

Scope: this envelope is the sampler's alone. It says nothing about the loss backends: both take the softmax in f32 (about 6e-7 relative at n = 8), and the CUDA path admits device logits that differ from the recorded ones by a per-row log-odds range of `2e-3 + 3e-3 * max|z|` plus a `5e-2` common shift (`bridge.rs:434-480`). Agreement with the production loss path is a separate receipt (section 6).

Thresholds: the envelope admits `P(i) = 0` once `p_i < (4n + 16) u`, that is beyond 32.9 nats at n = 8, 26.8 at n = 5,040 and 24.3 at n = 65,536. Sequential prefix-sum rounding can erase a small positive increment, and finite-grid interval alignment can also leave a positive weight with zero selection mass, so neither a relative-error bound nor a positive selection probability for every positive softmax mass is promised: the absolute envelope is the operative guarantee. A screen run makes a few hundred thousand learner decisions, so actions below 5e-15 are not drawn in practice. Codex countersigned this envelope under the pinned contract via the conservative threshold route (CODEX #552).

| Source | Bound |
|---|---|
| Gap subtraction: one rounding, `d~ = d(1+delta)`, `abs(delta) <= u` | `e^d~ = e^d (1+zeta)`, `abs(zeta) <= u abs(d) (1 + 8e-14)`. Since `p_i abs(d_i) <= 1/e`, this is at most `u/e` on `p_i`, and `u D` on `S` with `D = sum p_j abs(d_j) <= (n-1)/e` |
| `exp_v1` on exact `d` in [-708, 0] | relative `eta <= 4u` (budget `3.818u`). Reduction domain: `k` is the exact ties-to-even integer rounding of `y^ = fl(d * RN(1/ln2))` (the 1.5 * 2^52 shifter, exact for `abs(y^) < 2^51`); `abs(y^ - d/ln2) <= 1.3e-13`, so `abs(r) <= x_m = ln2/2 + 9e-14`. Horner: term j carries at most 2j+1 roundings, so `u e^x_m (2x_m+1)/(1-27u)` absolute, `3.386u` relative to `e^-x_m`. Reduction: the final subtraction, `fl(k * ln2_lo)` and the ln 2 split error (`1.2e-26` times `abs(k) <= 1021`) give `0.347u`. Truncation `x_m^14/14! e^(2x_m)`: `0.075u`. Coefficients (generic rounding of `RN(1/j!)`, j >= 3): `(e^x_m - 1 - x_m - x_m^2/2) e^x_m = 0.011u`. Products of these terms: below `2u^2` |
| Sequential sums | increment `C_i - C_(i-1) = w_i + delta_i`, `abs(delta_i) <= u C_i (1+2u)`: at most `u(1+2u)` per action; `abs(S - sum w) <= (n-1) u (1+2u) S` |
| Threshold product, strict comparison and draw grid | For a boundary value `c` (a prefix sum), let `G(c)` count grid points g with `fl(g 2^-53 S) < c`. `fl(x) <= x(1+u)`, so `x < c/(1+u)` implies `fl(x) < c`; `x >= c` implies `fl(x) >= c` because rounding is monotone and `c` is representable. Hence `ceil(2^53 F/(1+u)) <= G(c) <= ceil(2^53 F)` with `F = c/S`. The rounded product can only lower the count and the grid can only raise it by less than one point, so `-uF/(1+u) <= G(c)/2^53 - F < 2^-53`: under `u` per boundary, under `2u` per interval. The comparison is strict (`C_i > t`), so a tie `t = C_i` goes to the next index; `G(0) = 0` and `G(S) = 2^53` exactly because `u S < S` for every draw. Codex's conservative split (`u/(1-u)` arithmetic plus `u` grid per boundary) gives `2u/(1-u) + 2u` per interval instead |
| Tail floor | actions with `d < -708` get zero mass; all such mass is below `n e^-708 < 2.2e-303` |

Total (tight route): `(1 + 1/e) n u + 10 u` plus second-order terms below `1e-3 u` for `n <= 65,536`, hence `(11n/8 + 10) u + n e^-708`. The conservative threshold split gives `(11n/8 + 12) u + n e^-708`. The declared `(4n + 16) u` covers both for every `n >= 1`. (Amended after CODEX #528: explicit threshold and grid argument, reduction domain from the rounded product, generic coefficient term 0.011u, explicit higher-order terms. Contract and code unchanged.)

The fixture measurements check the implementation; the table above is the general argument.

Evaluation convention (disclosure): formal BO3 evaluation plays every endpoint, the trained students included, through the legacy deployment sampler, which quantizes logit gaps to 1/256 nat and clamps them at 16 nats. Qhat's behaviour law therefore differs from the evaluated law in two ways: the Q8 quantization perturbs every action's probability slightly (relative factor within about `e^(1/512)` per weight), and the clamp inflates actions more than 16 nats below the best (each below about 1.1e-7 relative mass under the unclamped law).

Still open: agreement with the production loss path (Codex #522 item 1; Fable changes 2 and 3 on the line (b) and lane entries). The CUDA GAE step reads the device logits back to the host and gates them against the recorded logits (`bridge.rs:434-480`); its reported `selected_log_probability` is a host f32 value refolded from the recorded logits (`bridge.rs:1641-1658`) and never sees the device forward. The receipt therefore uses the device's live root-row logits: the maximum log-probability discrepancy between that path and the collection softmax at selected roots, declared in log-probability units against the size of the teacher gradient (`c p_i d`; order 1e-3 or tighter, not the 5e-2 bridge gate), with the host refold check as a separate line.

### Wiring into collection

- `FrozenPlayPolicyV1` carries an optional collection sampler (`None` for every constructed policy). `sample_scores`, the one sampling point, takes one `next_u64` of the acting seat's stream and hands it to the unclamped sampler when the mode is set, so seat streams advance exactly as with the legacy samplers. Collection forks keep the mode; `with_legacy_collection_sampler_v1` drops it.
- `CollectionSamplerV1` (`legacy` default, or `unclamped-softmax-f64-icdf-u53-v1`) is a field of the Collect and CollectParallel commands and of the training-run config. It is omitted when legacy, so existing commands, configs, receipts and trajectories keep their bytes. It applies to the learner policy only.
- Learner rows record the unclamped identity at every width; the trajectory records `learner_sampler`. Opponent rows keep the legacy width rule. Validation replays every row with the sampler its identity names and rejects any mismatch, unknown identity or altered selection.
- On resume and before each update, the training-run driver checks that the collection receipt's `collection_sampler` and every trajectory's `learner_sampler` match the run config.
- Parallel collection gives a current-self opponent (an opponent whose source equals the learner's, which is the frozen g115 `initial` assignment at the first update) a fork of the learner policy. That fork now drops the collection mode, matching the serial loader; without this, g115 would have sampled with the learner's sampler in parallel runs only.
- Tests: serial Collect and CollectParallel publish byte-identical trajectories with the new sampler and with the legacy default; learner and opponent rows carry the expected identities; four tamper cases fail validation; legacy trajectories contain no new key; the policy draws one seat-stream value per decision and matches the sampler reference.

## 2. Head-only optimizer mask `line-b-head-only-mask-v1`

Code: `mtg-kernel/src/native_policy_train_step_v1/head_only_mask_v1.rs`; applied in `execute_update_v1` (`expanded_deck_training_v1.rs`) and selected by `line_b: {"optimizer_mask": "line-b-head-only-mask-v1"}` on the Update and UpdatePrepared commands and the training-run config (omitted when absent, so existing bytes and arithmetic are unchanged). Design countersigned by Codex (#522 item 2) and Fable (lane verdict, point 4).

- Topology: exactly the 33 tensors of `native_policy_train_step_v1.rs:521-591`, in order, with their shapes and matching moment layouts; any other name, order, count or shape is refused with a typed error, with no allow-all fallback. Trainable: `scorer.0.weight`, `scorer.0.bias`, `scorer.2.weight`, `value_head.0.weight`, `value_head.0.bias`, `value_head.2.weight`, `value_head.2.bias` (12,545 elements). `scorer.2.bias` stays frozen at its gauge anchor with zero moments.
- Mechanism: restore-after-step. Before the learner step the update keeps the full snapshot; after whichever backend ran (CPU reference or the CUDA bridge), the 26 frozen tensors' parameters and both Adam moments are copied back bit for bit, and the train state is rebuilt through `from_snapshot_v1` (which revalidates the manifest and the gauge) before the checkpoint is written. On CUDA the next step re-imports because the host snapshot no longer matches the resident export (`bridge.rs:401-425`). The update requires exactly one Adam age step and an unchanged gauge anchor.
- Receipts: each masked update publishes `line_b.frozen_tensor_sha256`, a domain-separated digest of every frozen tensor's name, parameter and moment bits. The training-run driver computes the same digest from the run's initial source and requires every update to repeat it.

Tests (debug, feature `experimental-burn-net8-packed-cuda-v1`): unit tests for the seven head tensors (12,545 elements), refusal of renamed, reordered, reshaped and truncated manifests and of a bad moment layout, restore rewinding every frozen byte while keeping the head updates, and the age and anchor checks. A real-game fixture through the Collect and Update commands with the production GAE loss on the CPU reference: after each of four updates every frozen tensor's parameter and both moments equal the initial state byte for byte, the receipt repeats the initial frozen digest, the Adam age advances by one per update, the gauge anchor is kept, all seven head tensors move, and the play policy's embedding table hash is unchanged; the same schedule without the mask moves the trunk within two updates (power check). The same fixture through the CUDA device-1 bridge (ignored by default; run explicitly on GPU 1) gives the same results on every check (passed 2026-09-27 on GPU 1). The pinned GAE ordinary-trainer golden, the run-driver suite (including a real two-iteration CPU run) and the update-preparation tests pass unchanged.

## 3. Root selection (`expanded_deck_training_v1/line_b_root_selection_v1.rs`)

- Seeds: Codex's production labels `screen-teacher/block/{bb}/update/{uuu}/slot/{ss}/{root|rollout}` (the slot is the game's slot in its update; zero padding 2/3/2) and `line_b_seed_v1(label)`, the unsigned big-endian first eight bytes of SHA-256("g115-line-b-seed-v1|" + label). A unit test pins five entries of Codex's manifest (`line-b-two-slot-seeds-v1.json`, 32bb5a35); all 8,034 entries re-derive offline with no mismatch.
- Eligibility: decisions the learner policy made (every row of a self-play episode, else the learner seat's rows, the rule the update's learner groups use), kind Surface, substep 0, 2 to 8 legal actions. Surface decisions are always substep 0 (`rl_session.rs:172-176`, `:1599-1602`); the substep-0 clause is kept as a guard (disclosure).
- Rank: SHA-256("mtg-kernel/line-b-teacher-root/v1\0" || root seed u64 LE || `kernel_search_visible_key_v4(0)`); the smallest rank wins, ties by the smaller physical decision id.
- Mechanism (changed from the design entry; same selection): the root is rebuilt by replaying the recorded trajectory from its episode seed instead of holding a session snapshot during collection, because the run driver passes trajectories from Collect to Update as files (`execute_v1` per command), so an in-memory snapshot cannot reach the teacher step. The replay builds the game through the same `episode_session_v1` call as collection, requires every recorded row (step, physical id, substep index and count, actor, legal action count) to match the live decision and the final terminal to equal the recorded one, holds only the current minimum's session, draws no RNG and leaves collected bytes untouched. A mismatch is an error, never a skipped game. A retried non-natural attempt records the seed it used, so the replay follows the attempt that produced the trajectory.
- Output: the row index, physical id, actor, rank, visible key, eligible count and the live root session (before its recorded action). The target's `z` is that row's recorded collection logits.

Tests (debug): pinned manifest seeds and labels; rank known answers (checked with hashlib); eligibility over widths 0 to 10, the three decision kinds and substeps; on one real self-play game (Burn mirror, fixture V4 policy): for eight root seeds the selected root equals the minimum found by an independent replay over every eligible decision, the eligible count matches, the root session is live at the recorded row with the recorded actor and the same visible key, and a fresh fork of the collection policy scores the replayed root to the recorded logits and value bit for bit (so rollouts can start from fresh forks at a replayed root); the seed moves the root; a repeat selection gives the same row, rank and state hash; a truncated trajectory, a changed episode seed and a widened recorded row each fail the replay; learner rows are both seats in self-play and only the learner seat against an opponent. The pinned GAE ordinary-trainer golden passes with the shared session constructor, so collection is unchanged.

## 5. Target and loss (math landed; integration pending)

Module `line_b_teacher_target_v1.rs`, version `line-b-teacher-target-f64-v1`. The divergence is one parameter with exactly two values, `reverse-kl` (`KL(p_theta || q)`, default, slot 1) and `forward-kl` (`KL(q || p_theta)`, slot 2). T, c and K are parameters with the declared values 0.25, 0.1 and 16, never tuned.

- Arithmetic: binary64 round-to-nearest-even without fused multiply-add or a platform math library, MXCSR verified on every public call (fail closed), so a teacher packet is bit-identical across hosts. `exp_v1` is the sampler's. `ln_v1` (for sums `S >= 1`) reduces `x = m 2^e` with `m` in `[sqrt(1/2), sqrt 2]` and sums `2 atanh((m - 1)/(m + 1))` to `t^23/23`: at most 2.33u relative error on [1, 65536] against a 60-digit oracle (5,802 points), within 2 ulp of the platform log, and exactly 0 at 1.
- Softmax: the sampler's tail rule and summation order (gaps from the first maximum, `w_i = exp_v1(d_i)` for `d_i >= -708`, else `+0.0`, summed from `+0.0` in legal-action order), so `S` equals the sampler's total bit for bit; `p_i = w_i / S` and `log p_i = d_i - ln_v1(S)`, finite even where `p_i = 0`.
- Mean return: `Qhat` is the mean of natural terminal returns in {-1, 0, 1} (anything else is refused), exact for K = 16.
- Target: `log q = log_softmax(z + (Qhat - max Qhat) / T)` with `z` the recorded collection logits (binary32, promoted exactly). This is the proposal's `log p_u + Qhat/T - LSE(...)`, computed with fewer roundings: the shift is exact for K = 16 and T = 0.25, and a zero shift leaves the logit untouched, so equal returns give `q` and `log q` equal to `p_u` and `log p_u` bit for bit.
- Reverse: value `sum p_i (log p_i - log q_i)` over `p_i > 0`; logit gradient `p_i ((log p_i - log q_i) - KL)`. Forward: value `sum q_i (log q_i - log p_i)` over `q_i > 0`; logit gradient `p_i - q_i`. The functions return one root's value and student-logit gradient; `c` and the mean over the batch's selected roots (censored roots kept in the denominator) are applied at integration.

Checks (unit tests, debug): the proposal's formula checks for p = (0.2, 0.3, 0.5), returns (1, 0, -1), T = 0.25 (`|sum q - 1| <= 4u`, observed 0; finite differences below 3e-11 for both directions, observed at most 6.0e-13; equal returns keep p within 1.2e-16, observed 5.6e-17); A1 at `p_theta = p_u`: the reverse gradient equals `-(1/T) p_i (Qhat_i - E_p Qhat)` within 1e-15 (observed 2.6e-16); A2: the forward gradient equals `p - q` bit for bit, and both gradients match fourth-order finite differences below 3e-11 on 248 menus of widths 2 to 8 (observed at most 4.6e-13); gradient sums: reverse `|sum g| <= 4u (sum |g| + n KL)` and forward `|sum g| <= 4nu` (observed at most 1.21 and 1.10 of those units); zero probability exactly where a gap falls below the tail floor, and `S` equal to the sampler's total bit for bit on every battery root; typed refusals for empty or oversized menus, non-finite logits, out-of-range means, non-natural returns, invalid temperatures and length mismatches. A 256-root golden battery (widths 2 to 8, 64 and 300; `-0.0` logits; a logit 800 nats below the rest; equal-return roots; students at and away from the collection logits) is pinned by SHA-256 `90d9e4639093111dc876079d37cdd2d02ea8476003cc1a3e31d038091192a38f`, which `python/tools/line_b_teacher_target_v1_replica.py` reproduces (`--oracle` and `--margins` print the measurements above).

Disclosure: the proposal states its finite-difference check without a stencil. A plain central difference at h = 1e-6 carries about 2.5e-10 of rounding noise, above 3e-11, so the tests use the fourth-order stencil at h = 1e-3.

Integration (next units): the binary64 gradient scaled by `c/N` and rounded once to binary32 at the existing logit-gradient seam of the CPU reference, the CUDA device-1 path, derived gauge-residual terms for both directions on both backends, and permuted controls.
