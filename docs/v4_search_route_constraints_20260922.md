## Evaluation adapter design questions from the source audit

Do not implement fallback by catching all state errors. The initial core erased typed V4 errors into debug strings and conflated sampler rejection with post-sampling reconstruction failure. The current maintenance patch retains StateStage(Key/Redeterminize/Token/Consume) and the typed V4 source. Post-sampling candidate rebuild, boundary encoding and boundary equality failures have distinct variants. HiddenStateContract remains the sampler rejection category. Focused controls-006 completed33/33pass in0.78stest/278.4475828sinvocation, with all13sourcepins unchanged. Existing controls distinguish original sampler rejection from injected post-sampling visible corruption. No error has become recoverable and no fallback action is introduced.

A fallback branch can itself affect play, so its eligibility must be invariant under supported root-hidden rearrangements. In particular, do not assume a check over privileged state is safe merely because its result is an error. Show that intended ineligibility follows the root-visible contract, or reject the entire engineering/evaluation run on unexpected sampler failure. Visible decision-local library roots and insufficient explicit work/headroom can have separately declared handling. Invalid bindings, tensor mismatch, nonfinite evaluation, failed stepping and corrupted trees must not be silently converted into ordinary actions.

Keep native training guards unchanged. The current BO3 RecordingPolicy computes behavior from ordinary logits after selecting the ordinary action. A new evaluation adapter must either carry a separately typed evaluation decision (ordinary stochastic versus deterministic search with diagnostics), or provide an explicitly reviewed equivalent actual behavior representation with structural training exclusion. It may not pass ordinary logits off as search behavior. Preserve the existing match coordinator's registration, chooser/starting-player coupling, opening and sideboard semantics, and seed resets. A separate route must validate/load the actual search descriptor, not silently rewrite it to Disabled to pass current loaders.

These are integration requirements and unresolved design choices, not new gate or launch authority. Resolve after the consumed-root replay supplies production-surface evidence, then request the focused adapter review before substantial evaluation.

Follow-up source audit: package.rs load_supported_components_v1 validates metadata, keeps the explicit Disabled predicate, verifies runtime and then binds actually loaded inference identity/sampler and sideboard bytes. A new evaluation loader must reuse those identity checks without rewriting search to Disabled. Collection validation and RecordingPolicy are native-training-specific; a search action cannot be inserted behind select_paired_with_scores_v1 while retaining Hamilton probabilities. Use a separate evaluation record and match-driver adapter with the original match coordinator. Successful diagnostics establish fresh leaf/core behavior at two consumed roots, not a broad availability policy. HiddenStateContract currently includes privileged object residue/reference checks, so its enum label alone is not permission for ordinary-policy fallback.
