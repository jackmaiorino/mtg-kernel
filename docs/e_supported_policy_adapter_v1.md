# E supported-choice policy adapter

The `e_supported_update` command in `ExpandedTrainingCommandV1` adds the frozen E teacher's supported executed choice to an ordinary CPU GAE update. It takes the existing source and trajectory pins, ordinary optimizer scalars and GAE loss selection, plus `ESupportedTeacherOptionsV1`. Architecture, collection/deployment sampler, signed-terminal GAE/value targets and full inherited Adam remain unchanged.

Each scheduled slot names a trajectory and a registered stable case ID. The adapter replays that ordinary-start trajectory, outcome-blindly hash-ranks every nonforced learner substep, and retains the minimum. All decks, widths and decision families are eligible. It verifies the complete live tensor against both the stored row and prepared forward row. A reset cut is refused because it lacks a complete pre-root visible prefix. Forced focal frames are retained in that prefix even though they are not query candidates.

An independent cloned E query uses B1, FPU1.5, depth32, repaired-v2 keys with conservative fallback, the public deck prior and separate role seeds. The prior retains physical public/known-card multiplicities seen along the prefix. A supported root choice requires eight natural backups. Its canonical edge is inverted through the same Keyer/storage menu into one exact live legal action index, retaining duplicate occurrence identity and full menu width. The packet contains raw actor-visible observations, ordered action semantics, history, canonical/live permutation, counts, tie order, target bits, student action, input hash, runtime/build/binary and model identities, cost counters, unavailable status, CE, deployed Hamilton mass, disagreement and census by deck/seat/family/width.

The supervised channel is `0.1 / scheduled_slots * sum(valid CE)`. It reuses the source-verified forward-KL reverse machinery with an exact one-hot target. There is no synthetic on-policy row, value target, outcome or disagreement weight. All auxiliary and ordinary gradients combine before one continuing full Adam step, with the existing scorer-bias gauge. Receipts expose whole-parameter and policy/shared/value-head norms, ratios and dot products. The auxiliary value-head derivative is zero; shared-trunk changes can affect later value predictions. Existing ordinary `loss` remains ordinary; `gradient_exposure.total_loss` reports ordinary loss plus CE in binary64.

Missing support or no eligible row retains its scheduled denominator. No valid targets, an empty schedule, or `treatment:false` calls the original ordinary update without added-zero gradient arithmetic. Control queries still retain support/CE/deployed-mass/disagreement records. An empty persistence schedule loads no teacher and queries no targets. Packets are generated anew each update and never replayed as later training labels. Instrument faults, stale/ambiguous action or input bindings and nonfinite logits stop publication.

The target packet is durably published before its checkpoint; the checkpoint binds the packet pin and the method/teacher/runtime/treatment identity. The final update receipt is the completed-update publication marker. Subsequent updates must use the E command and preserve that continuation identity. Ordinary inference/checkpoint restoration retains full parameters, Adam moments and age.

Affected checks use `cargo +1.94.1 test --locked -p mtg-kernel --lib e_supported` and the existing `gae_v1` checks. Engineering fixtures cover duplicate action binding, support/ties/corruption, visible-history identity/prior consistency, finite loss/backward, zero direct auxiliary value gradient, shared-trunk exposure, combined inherited Adam, treatment-zero equivalence and deterministic primary-state/packet replay. These are engineering checks, not playing-strength evidence.

This is an engine prerequisite. It adds no pilot run scheduler, source-outcome selection, new experiment arm or strength evaluation.
