The current source confirms the relevant transport gap. `mtg-kernel/src/rl.rs` projects kicked, is_flashback, cast_method, mode_chosen and x_value into public stack items. `flat_policy_v2.rs::stack_payload` preserves them in `FlatStackRelationDataV2`. In `native_flat_tensorizer_v2.rs`, the StackTarget edge builder emits an empty numeric payload, while the canonical stack serializer includes the attributes. The public-feature extension does not fill this gap: `public_cost_features_v1.rs::from_actor_v4_v1` produces six global prevention bits and static token-indexed cost rows only.

The candidate contract should expose public stack semantics through a separately versioned dynamic projection. It must retain each stack item's order/identity, including untargeted spells, triggered/activated abilities and copies. A card-token lookup alone is insufficient: multiple stack items can share a source or printed card identity while having different attributes. Do not rely solely on emitted object-target edges, since untargeted and player-targeted items need coverage too.

Before implementation, specify explicit presence and spell/ability distinctions, categorical cast method and mode, a documented X encoding/range, kicked/flashback flags, and behavior for multiple instances or absent fields. Consume only the validated actor-visible projection. Bind the new contract and projection weights into checkpoint, optimizer, trajectory and deployment identity. Preserve existing v1 artifacts and loader behavior.

Acceptance should include actual engine-generated kicked/flashback/modal/X cases, copies and multiple same-source stack items; both actor seats; hidden hand/library perturbations with identical visible features/actions; exact legacy behavior with the new projection disabled or zero initialized; saved-row replay and gradient/optimizer continuation with nonzero new weights. An explicit invariant must catch missing or misaligned dynamic rows, not infer correctness from catalog tokens.

A later matched ablation should change only this feature group, using frozen terminal rewards, opponent/schedule controls, matched seeds and complete-panel gates. Do not bundle card-face, cost, stack and learning-loss changes into one uninterpretable arm. The failed prevention replication prevents claiming that exposing another omitted field will necessarily improve play. First preserve the replication result and qualify the next diagnostic design.
