# Search-playing integration boundary, 2026-09-22

This is preparation, not a launch contract. E-12/E-14 search direction is adopted and the teaching line remains closed. Two-root execution is necessary feasibility evidence, not a whole-match effect estimate. The user goal remains competitive play and M1 through M5 in order.

Current hard boundary: phase1_agent_v1/package.rs:456 and phase1_bo3_collection_v1/mod.rs:253 require disabled search in supported execution. The old KernelNativeDescriptorV1 is metadata only, and model_guided_search_authority_v1.rs:245 limits its seed blocks to S0/S1 engineering/feasibility. Do not set Disabled while overriding actions, reinterpret diagnostic reports as playing authority, admit old search descriptors, or broaden seed lists. A new supported search candidate needs an explicit versioned identity, strict validated loader and collector integration with all base-model/runtime/source pins preserved. The existing package hashes and search-disabled path must retain their meaning.

Minimum proposed identity fields: base complete-agent package hash, public certificate algorithm/schema and whitelist hash, transition/depth/menu limits, deterministic branch tie-break, strategy binding/lifetime, fallback and RNG-consumption contract. The base model advances its sampling stream exactly once per own decision. Unknown/unsupported roots fall back before any intervention; a strategy mismatch after intervention is a recorded engineering failure, not a certified result. Live policies may consume only typed visible recommendations from a separately reviewed boundary, never copied hidden state. Reusing a diagnostic's whole exact engine copy as a public oracle is not automatically acceptable.

Measurement obstacle: the current two certified roots are selected and both original games were wins. No useful 2pp effect is identified or forecast. Do not launch a nominally powered 2pp trial on that assumption. An n=0 training search wrapper is a fixed inference intervention; the measured s=.76pp between-training-run SD still must be stated and used when claiming lineage-level robustness, not substituted for paired evaluation uncertainty. Future analysis must identify its unit, evaluate effect/power using observed endpoint vectors and seed-pair clusters, retain all replications, and use1.39pp sensitivity. No silent noninferiority margin or CP7-based policy selection.

Next design decision: can the supported policy achieve adequate opportunity coverage at useful latency, or does the narrow certificate need a broader information-set search candidate before any whole-match gate? Existing model_guided_search_core_v1.rs uses a V2 tensorization/real-forward seam (around256-275), while the incumbent is V4; compatibility is unproved. Do not connect it by casting generation identities or dropping features. Literature in collab/lit/20260922-search-redirect-preparation.md motivates information-set reasoning and base-policy lookahead, not automatic gains. A concrete new proposal needs a fresh independent review before implementation of a playing route, and a specific literature/power/guarded-compute contract before measurement.
