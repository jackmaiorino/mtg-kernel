The attempt003 local guarded launcher and all its native children disappeared without a terminal receipt. The exact cause is unobserved. This motivates separating future worker lifetime from the dispatching tool; it does not establish that the backend killed the run.

The dispatcher requires fresh worker/control roots, pins its own script plus manifest and launcher hashes, runs the supported check-only preflight and refuses live competing native work immediately before launch. Any future use still requires fresh fleet admission and a full new formal attempt under the reviewed interruption rules.

Microsoft documents that WMI-created processes do not inherit the caller's job association: [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects). The actual local probe confirms this property. `E:/mtg-g115-lineage-20260923/durable-owner-probe-001/verification.json` records a harmless20-second Python process, created hidden through WMI, which reported `in_job=false` and completed after the calling PowerShell process exited. Both exact processes were confirmed terminal. Evidence includes the dispatch, PID/creation time, start and completion records. No native simulation or evaluation ran.

These checks establish the transport mechanism and overwrite refusal, not successful formal execution. No forced Codex shutdown was tested; no guarantee against reboot, user cancellation or worker failure is claimed. The transport has not yet launched a formal worker.
